# 数据库设计

数据库使用 Oracle 18c，初始化脚本按编号执行。完整的目录级维护说明见 [`database/README.md`](../database/README.md)：

- `01_schema.sql`：最终表结构、主键、外键和检查约束；
- `02_indexes.sql`：唯一约束之外的业务唯一索引和查询索引；
- `03_rbac.sql`：默认角色、权限和角色权限关系；
- `04_demo_users.sql`：本地演示账号和用户角色关系；
- `05_seed_core.sql`：论坛、帖子、商品等核心演示数据；
- `06_seed_scenarios.sql`：媒体、收藏、钱包、通知、订单和仲裁等跨模块场景。

## 范式约定

结构按第三范式组织：每张表描述一种事实，非键字段只依赖该表主键。

- 商品仅保存 `categoryId` 和 `conditionId`，名称及说明分别由 `ProductCategory`、`ProductCondition` 维护；
- 媒体元数据只存于 `MediaFile`，帖子、商品和头像分别通过 `PostMedia`、`ProductMedia`、`UserAvatar` 关联；
- 图片顺序属于“内容与媒体的关系”，因此保存在关联表，而不是媒体文件表；
- 多对多关系均使用复合主键关联表，如 `UserRole`、`RolePermission`、`FolderPost`；
- 钱包、用户名、邮箱、板块、收藏夹名称等业务键由唯一索引约束。

API 仍使用易用的展示模型，例如商品响应返回分类名称及 `imageUrls` 数组；这些值由关联查询组装，不是数据库中的重复字段。

## 演示数据

预置数据包括 4 种角色账号、7 个论坛板块、12 篇帖子、9 件商品、评论、点赞、收藏夹、好友与私信、通知、钱包、订单留言、举报、纠纷和仲裁结果，可直接用于主要页面和业务链路演示。

本次结构为不兼容的干净重构。已有开发数据卷不能原地沿用，需在确认数据可丢弃后执行：

```bash
./scripts/restart.sh --reset-data --wait
```
