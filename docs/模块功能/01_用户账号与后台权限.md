# 用户、账号与后台权限

负责人：成员 1

## 功能范围

本模块负责系统账号体系和后台权限基础能力，是其他模块的鉴权入口。

## 具体功能

### 注册与登录

- 用户使用用户名、密码、邮箱等信息注册。
- 注册时校验用户名和邮箱唯一性。
- 支持校园实名准入，可以通过学号、校园邮箱或实名字段进行校验。
- 用户登录成功后返回访问令牌和用户基础信息。
- 登录失败时返回明确错误，不暴露敏感信息。
- 支持多角色登录后识别用户角色。

### 个人资料

- 查看当前用户资料。
- 修改昵称、头像、联系方式、个人简介等资料。
- 限制用户只能修改自己的资料。
- 管理员可查看用户列表和用户详情。

### 密码重置

- 用户通过邮箱申请密码重置。
- 生成验证码或重置令牌。
- 校验验证码后允许设置新密码。
- 新密码需要重新加密保存。
- 旧密码不能继续登录。

### 后台权限

- 管理角色列表。
- 创建、编辑、删除角色。
- 管理菜单权限和接口权限。
- 给用户分配角色。
- 普通用户不能访问管理员接口。
- 管理员入口需要在前端隐藏或禁用无权限菜单。

### 信用分基础

- 用户表维护信用分字段。
- 用户个人资料页展示信用分。
- 管理员可查看和调整信用分。
- 信用分变更需要记录原因、变更前后分值和操作人。


## 测试要求

- 注册成功。
- 重复用户名或邮箱注册失败。
- 正确密码登录成功。
- 错误密码登录失败。
- 未登录访问个人资料失败。
- 用户修改自己的资料成功。
- 用户修改他人资料失败。
- 邮箱验证码重置密码成功。
- 旧密码登录失败，新密码登录成功。
- 普通用户访问管理员接口失败。
- 管理员创建角色、分配角色成功。
- 信用分调整后记录流水。

指定测试文件：`test/tests/test_auth.py`

## 验收标准

1. 普通用户可以完成注册、登录、资料维护和密码重置。
2. 管理员可以完成角色和权限配置。
3. 无权限用户无法访问后台接口。
4. 其他模块可以复用登录态、用户身份、角色权限和信用分字段。


## 现状

- 与图片上传通道相关的共用改动：
  - 系统新增媒体上传服务与控制器（`MediaController`, `IMediaStorageService`）；
  - `/api/media/images` 已作为独立接口提供，支持 `posts/products/avatars` 目录上传，最大 6 张/次，限制 5MB 与支持类型（jpg/png/gif/webp）；
  - 存储逻辑支持本地文件系统与 S3 兼容对象存储（MinIO）；项目默认部署通过环境变量切换 provider；
  - 本地场景使用 `wwwroot/uploads/{bucket}`，对象存储场景通过 `/uploads/{bucket}/{key}` 统一透出给前端。
- 用户相关：
  - 头像上传依旧走 `POST /api/user/avatar`，使用同一媒体服务完成实际存储与权限边界，上传后头像 URL 写入 `AvatarUrl`。
- 数据层：
  - 新增 `MediaFile` 表（`database/09_media_file.sql`）用于统一存储媒体元数据，当前模块涉及的帖子/商品图片从“纯 URL 数组”逐步切换到 `MediaFile` 关系读取。
