# 信用分复用

## 字段含义

| 字段 | 含义 |
| --- | --- |
| `User.credit` | 当前信用分，用于业务准入，范围 0–1000 |
| `User.totalCredit` | 累计正向实际加分，用于等级成长 |
| `User.userLevel` | 由累计积分计算的等级，只升不降 |
| `CreditAdjustment` | 每次信用变化的审计流水 |

业务代码不得直接修改 `User.Credit` 或手工插入流水，应复用 `ICreditService`。

## 准入检查

```csharp
if (!await _creditService.CanPerformAsync(userId, "post"))
    return BadRequest(new { message = "信用分不足或账号不可用" });
```

当前阈值：

| operation | 最低信用分 |
| --- | ---: |
| `post` | 60 |
| `comment` | 40 |
| `product.publish` | 50 |
| `order.create` | 50 |
| 其他值 | 大于 0 |

用户不存在或状态不是 `Active` 时一律拒绝。新增业务动作时，应在 `CreditService.CanPerformAsync` 中定义明确阈值并补测试。

## 调整信用分

```csharp
var adjustment = await _creditService.AdjustCreditAsync(
    userId,
    -20,
    $"纠纷 #{ticketId} 仲裁成立",
    operatorId);
```

`AdjustCreditAsync` 会：

- 将当前信用分限制在 0–1000；
- 流水记录裁剪后的实际变化值；
- 仅把正向实际变化累计到 `totalCredit`；
- 根据累计积分提升等级；
- 记录原因、操作人、调整前后分值和时间。

用户不存在时返回 `null`。原因应描述业务来源和目标编号；人工操作传当前操作人，系统任务可传 `null`。

`AddCreditAsync` 是无法记录操作人的兼容入口，新代码优先使用 `AdjustCreditAsync`。

## HTTP 接口

```text
GET  /api/user/{userId}/level
GET  /api/user/{userId}/credit
GET  /api/user/credit-adjustments
GET  /api/user/{userId}/credit-adjustments
POST /api/user/credit/add
```

所有接口均依赖 Cookie 登录态；查看他人记录和调整信用分还需要相应用户管理权限。精确请求模型和响应结构以 Swagger 为准。

## 接入检查清单

- 操作前调用正确的 `CanPerformAsync` operation；
- 调整时记录可审计原因和操作人；
- 不信任请求体提供的当前用户 ID；
- 测试覆盖阈值上下边界、非 Active 用户、上下限裁剪和流水字段；
- 涉及事务的业务，应确认业务状态与信用流水的一致性边界。
