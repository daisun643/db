# 项目介绍与功能

## 1. 项目定位

同济论坛是面向校园场景的综合社区系统，将论坛交流、社交私信、闲置交易和后台治理整合在同一套账号、权限、信用与通知体系中。项目提供可直接运行的前后端、Oracle 初始化脚本、对象存储和 HTTP 集成测试。

## 2. 技术架构

| 层次 | 技术与职责 |
| --- | --- |
| Web 前端 | Vue 3、Vite、Vue Router、Pinia、Axios；提供论坛、市场、消息和后台页面 |
| API 后端 | ASP.NET Core 8、EF Core；负责认证、授权、业务规则、事务和事件通知 |
| 业务数据库 | Oracle 18c XE；保存用户、内容、订单、钱包、权限和审计数据 |
| 媒体存储 | S3 兼容存储，开发环境使用 MinIO；统一保存帖子、商品和头像图片 |
| 测试 | pytest + requests；通过真实 HTTP 接口验证业务闭环 |
| 运行环境 | Docker Compose；统一编排前端、后端、Oracle 和 MinIO |

系统使用 Cookie 登录态。角色与权限写入服务端签发的 Claims，后端同时检查权限和资源所有权；前端路由与菜单控制只用于改善交互体验。

## 3. 功能模块

### 3.1 账号、资料与权限

- 同济邮箱验证码注册、登录、退出和当前用户查询；
- 忘记密码、验证码用途隔离、密码修改；
- 昵称、联系方式、简介和头像维护；
- `Manager`、`Moderator`、`User` 等预置角色；
- 系统预置角色与权限，业务运行期间不提供动态创建或分配；
- 后台入口和敏感 API 的服务端权限校验。

### 3.2 信用与积分

- 当前信用分控制发帖、评论、发布商品和下单资格；
- 信用调整记录调整前后分值、原因、操作人和时间；
- 举报、审核和纠纷处理可复用统一信用服务。

### 3.3 论坛内容

- 版块浏览与管理、版主分配；
- 图文发帖、编辑、删除、详情和浏览量；
- 评论、嵌套回复、删除占位；
- 点赞、取消点赞、收藏夹与收藏管理；
- 按关键字、版块、状态和时间组合检索；
- 分页和 `X-Total-Count` 总量响应头。

### 3.4 内容治理

- 敏感词触发待审核状态；
- 审核通过、拒绝及结果通知；
- 帖子置顶、加精、封禁和删除状态流转；
- 帖子、商品举报及管理员审核；
- 管理范围和资源所有权隔离。

### 3.5 社交与通知

- 好友申请、接受、拒绝和好友关系管理；
- 私信会话、消息发送和会话摘要；
- 通知列表、类型筛选、分页、单条/全部已读和删除；
- 回复、提及、举报、审核、订单和纠纷等业务事件通知。

### 3.6 商品与库存

- 商品发布、编辑、详情、下架和重新上架；
- 分类、成色、价格、库存和多图展示；
- 关键字、状态、分类、成色、价格/库存/时间区间筛选；
- 最新、价格和库存排序以及稳定分页；
- 下单时通过数据库条件更新防止库存超卖；
- 锁定、售出和下架状态约束。

### 3.7 订单、钱包与纠纷

- 买家下单、支付、取消和确认收货；
- 钱包余额、冻结资金、卖家结算和资金流水；
- 买入/卖出订单筛选与分页；
- 仅买卖双方可访问的订单留言板，结束后只读归档；
- 买卖双方发起纠纷、仲裁员分配、补充材料；
- 全额/部分退款、责任方信用处理和结果通知。

### 3.8 图片与对象存储

- 统一的 `/api/media/images` 上传入口；
- 支持帖子、商品、头像目录，单次最多 6 张；
- 校验 JPG、PNG、GIF、WebP 类型、文件签名和 5 MB 大小限制；
- `MediaFile` 保存归属、顺序、上传人和存储地址；
- 开发环境使用 MinIO，读取时兼容历史图片 URL。

## 4. 主要页面与接口域

前端页面包括首页、登录注册、找回密码、论坛、市场、消息中心、个人资料、资金流水和系统管理。

后端接口按业务域划分：

| 接口前缀 | 业务域 |
| --- | --- |
| `/api/auth`、`/api/user`、`/api/rbac` | 认证、资料、信用、权限 |
| `/api/forums`、`/api/posts` | 论坛与帖子 |
| `/api/friends`、`/api/messages`、`/api/notifications` | 社交与通知 |
| `/api/products`、`/api/transactions`、`/api/wallet`、`/api/finance` | 商品、订单与资金 |
| `/api/reports`、`/api/audits/posts`、`/api/disputes` | 举报、审核与仲裁 |
| `/api/media`、`/api/health` | 媒体与健康检查 |

精确请求模型、权限要求和响应字段以运行中的 Swagger 为准：`http://localhost:8080/swagger`。

## 5. 核心业务约束

- 未登录用户只能访问公开内容和认证入口；
- 权限必须在后端验证，不能信任前端隐藏、角色 ID 或请求体中的当前用户 ID；
- 发帖、评论、商品发布和下单前检查账号状态与信用阈值；
- 商品库存扣减和订单创建位于同一事务，库存不能小于零；
- 支付、结算、退款和订单状态变化必须保持事务一致性；
- 非公开、已封禁或已删除内容按角色和所有权控制可见范围；
- 订单留言仅参与方可见，完成、取消或退款后只读；
- 图片类型、大小、数量、归属和展示顺序由服务端统一管理。
